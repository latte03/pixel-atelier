# 游戏接入约定

这是适配说明，不是已连接全部引擎的插件。按你的游戏渲染器、状态机和碰撞系统落地。

## 保持原生尺度与根节点

输出配置中每帧的`rect`是图集裁框，`pivot`是完整帧中的逻辑根节点。画布留白可以不同；角色的原生像素尺度要一致。

下面是Canvas2D绘制示意，atlas/config/frame由游戏资源加载器提供：

```javascript
function drawPose(ctx, atlas, frame, rootX, rootY, face, pixelScale = 1) {
  const [sx, sy, w, h] = frame.rect;
  const [px, py] = frame.pivot;
  ctx.save();
  ctx.imageSmoothingEnabled = false;
  ctx.translate(rootX, rootY);
  ctx.scale(face * pixelScale, pixelScale);
  ctx.drawImage(atlas, sx, sy, w, h, -px, -py, w, h);
  ctx.restore();
}
```

朝向围绕角色root翻转。不要因帧画布由160变224，就把整帧缩回同一边长；应继续按各自pivot和同一pixelScale画。

## 让状态控制动作

- 待机/奔跑可循环。
- 攻击通常完整播到收势；连续按键是否接招由输入和状态机处理。
- 蓄力在明确区间保持，松键进入释放段。
- 倒地可保持最后一帧；起身需要独立出口或明确兜底姿势。
- 跳跃、冲刺、击退的世界坐标来自代码；美术帧负责局部姿态。

## 让事件对上剑路

`events.strikes`索引的实际时间为`frames[index].start_ms`。游戏时钟跨过事件时只触发一次，低帧率也不能漏事件。多段连招的命中集合按阶段重置，同一个目标在同一阶段不重复结算。

工作台单动作和整套导出的 `animation.json` 都提供 `events.strikes`（命中）和 `events.releases`（离弦或施法释放）。这两个字段存在时，值为零起始索引列表。没有标记的动作可读为无事件。也可以直接读取按时间排序的 `event_timeline`，每条包括 `type`、`index` 和 `start_ms`。前一姿势的停留时长更新后，后续事件的 `start_ms` 随下一次导出更新。

预览使用游戏绘制倍率时，仍应在引擎内按事件触发抛射物、有效窗口和受击反馈。 `technical.warnings` 记录输出帧的贴边或全不透明情况，`index` 为零起始。工作台同时检查源格和编辑偏移，源图本身是否裁断需要查看图表。

根据剑刃扫过的方向、距离、高度和短有效窗口建立攻击体积；角色图整张画布、完整发光像素区都不直接等于伤害区域。判定图形如果只是阶段近似，应在交接中注明。

## 挑飞需要敌人状态

上挑接触时为敌人设置向上速度。以后每次更新应用重力、更新高度，到地面后归位并触发一次落地反馈。需要处理敌人重量、免疫/霸体、空中死亡、奖励去重和状态恢复。数值由实际角色和游戏节奏调，不直接复制案例。

固定测试场景可以使用高血量或无敌来反复观察动作，录像要注明。再用正常敌人与实际关卡复核，才能判断难度与玩法平衡。

## 交接最少记录

- 原游戏入口、资源版本和来源哈希。
- 控制键、动作与事件映射、原生绘制倍率与相机倍率。
- 碰撞近似方式、命中窗口和去重策略。
- 实机截图、录屏、已跑测试、未覆盖场景。
- 缺少的格挡/起身/空中受击等姿势及兜底方式。
- Agent复核、用户视觉确认和正式定稿分别记录。
