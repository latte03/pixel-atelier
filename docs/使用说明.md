## 新增：角色工程工作流

使用顶部或「作品」页的「＋ 新建角色」，填名字即可创建空白工程，再进入创作填写想法和添加素材。已有工程的多个动作可在右上角「角色工程」中管理。

1. 点「复制女骑士完整模板」，创建独立工程；也可以从当前时间轴新建，或导入角色工程JSON。
2. 在动作列表打开待机、奔跑或连段。修改位置、时长会保存到对应动作，不覆盖其他动作。
3. 需要做新版本时，点「复制为独立工程」；原工程保留。
4. 在「角色与装备规格」中查看人物与武器描述。修改描述只影响后续生成，不会自动重画已有素材。
5. 新生成/导入的动作确认切帧后，通过动作槽与「将当前时间轴加入此动作」纳入工程。已有槽位不会被未绑定的时间轴静默覆盖。
6. 点「从全部动作冻结色板」，生成此工程统一使用的色板。已有模板已冻结；新增特效颜色后可重新冻结并复核全套。
7. 「导出整套角色资源」会检查每个动作的画布、锚点、裁切和透明帧，再将全部动作打成ZIP。失败时按提示校准，不会声称导出成功。
8. 「下载可编辑工程JSON」保存完整多动作工程；用「导入角色工程」恢复为独立工程。

自动保存分两层：浏览器IndexedDB保存当前工作草稿；角色工程同时保存到本机服务的`work/image-workbench/projects/`。右上角显示实际保存状态，默认约600ms后保存。刷新会恢复源图、时间轴、选中帧、角色工程与新手步骤。浏览器清理站点数据会影响本地草稿，因此重要节点仍建议下载JSON备份。

角色工程保存带修订号检查。如果另一页面已更新同一个工程，会提示保存失败并保留本机草稿；先下载本地工程JSON备份，再重新打开服务器工程，不要直接覆盖。历史版本位于工程目录的`history/`中，目前没有历史恢复界面。

进阶编辑的「替换当前完整帧」接收与原生画布同尺寸、具有真实透明区的PNG。它替换当前完整人物姿势，其他帧不变；当前帧偏移重置为零，可再微调。点「撤销替换」可撤销最近一次替换，切换源图后该撤销不再适用。此功能不会调用模型自动重画坏帧。

本机新增紫袍骷髅法师测试工程，包含待机、奔跑、法杖施法和受击。法杖工程使用施法提示词，首页舞台仍是原有女骑士示例，不代表法师生成预览。

## 1. 先认识工作台

你可以从三个入口开始：

| 手头有什么 | 使用入口 | 会发生什么 |
|---|---|---|
| 想先体验，没有自己的素材 | 首页动作卡片 →「免生成，直接用示例练手」 | 打开已有女骑士动作，直接播放、导出，不调用生图 |
| 一张角色参考图 | 新手模式 →「上传我的角色」 | 选择动作后提交生图，得到图表，再检查、切帧与导出 |
| 已经生成好的动作图表 |「打开图表 / 项目」 | 选择排版、切帧与导出，不调用生图 |

首页舞台播放的是已有示例。选中自己的角色后，舞台仍用于展示动作示例；只有生成任务完成后才能看到自己角色的新动作。

当前八类动作是：待机、奔跑、闪身、巨剑连段、蓄力重斩、跳跃、受击、击倒。动作预设的发力设计主要围绕双手巨剑。其他武器需要在进阶模式中修改要求，暂时没有经过完整的多武器验证。

### 先理解四个词

- **参考图**：告诉生图模型这个角色长什么样，不会自动变成可播放动画。
- **动作图表**：将不同姿势放在一张规则网格图片里，一格一个完整人物。
- **帧**：时间轴上的一个姿势。连续显示不同帧，就形成动画。
- **根节点 / 锚点**：游戏放置角色时使用的固定逻辑位置。它可以保持不动，同时允许角色屈膝或跳起来。

## 2. 打开与启动

### 当前这台电脑

打开 [工作台](http://127.0.0.1:8898/?ui=guided)。如果出现旧界面，刷新页面。

这是本机地址，其他人直接复制这个网址，无法访问你电脑上的工作台。他们需要自己运行项目，或另行部署适合多人使用的服务；当前版本没有多人服务部署流程。

### 独立启动工作台

在项目根目录执行：

```bash
python3 -m pip install -r requirements.txt
python3 bridge/server.py --port 8898
```

服务启动后访问 `http://127.0.0.1:8898/`。终端需要保持运行。

本地切帧和导出依赖 Python 与 Pillow。要提交生图，还需要本机安装、登录 Codex CLI，并且当前账户/模型通道能使用内置生图。页面“本机桥接已连接”只说明本地服务可连接，不能保证下一次生图一定成功。

### 从 DSH 面板使用

本机已配置 DSH 时，可以执行：

```bash
python3 bridge/launch.py --open
```

启动器使用独立的 `pixel-atelier` profile，工作台端口为 8898，DSH 端口为 8899。进入 DSH 后选择侧栏「像素角色工作台」。首次界面若出现说明，可点「继续」；本机生图链路不依赖 DeepSeek API Key，此处可「稍后配置」。

首次安装 DSH 或 Codex CLI 的系统级安装过程不在本说明内。也可以先只运行独立工作台。

## 3. 第一次使用：用示例练手

建议先走这条路线，熟悉播放和导出，再消耗生图额度。

1. 在首页下方点击一个动作，例如「巨剑连段」。
2. 观察舞台动作；点击右下角播放/暂停按钮，可以停住查看。
3. 点击「免生成，直接用示例练手」。
4. 进入简化预览。此时示例原有的完整帧、帧时长、缩放与锚点已经载入。
5. 点击播放，或逐帧检查。
6. 点击「制作并下载 GIF」。等待资源整理完成后，选择「下载 GIF」或「下载完整资源包」。
7. 想继续修改，点击「精细调整」；想换动作，点击「返回创作」。

「使用示例女骑士」与「免生成练手」用途不同：前者把女骑士设为参考，随后仍需要点击生成；后者直接加载已有动作，跳过生图。

本机示例没有默认放进公开代码或分享包。其他人运行源码后可能看不到女骑士，仍可上传自己的角色或图表。

## 4. 用自己的角色生成动作

### 4.1 准备参考图

支持 PNG / JPG，单个上传文件不超过 12MB，角色参考图不超过 1600 万像素。

参考图建议满足：

- 一个完整人物，尽量没有其他角色和遮挡。
- 发型、服装、配色、武器细节清楚。
- 手脚与完整武器都在画面内，四周留出空间。
- 本身就是希望延续的像素画风；缩小普通插画不会自动成为稳定的像素美术。
- 优先使用有真实透明背景的 PNG。JPG 可以用作生成参考，但作为图表导入时，工作台不会自动移除它的背景。

### 4.2 选角色

在首页点击「上传我的角色」，也可以直接把图片拖到上传框。上传成功后会进入选动作步骤。

你也可以点击「从我的素材库选择」，复用之前保存的参考图。

### 4.3 选动作

选择一个动作，再选动作细节：

| 选项 | 新手模式请求排版 | 适合如何使用 |
|---|---|---|
| 标准：8 个关键姿势 | 4 列 × 2 行 | 先验证人物和动作是否合理，减少第一次检查量 |
| 更丰富：16 个关键姿势 | 4 列 × 4 行 | 增加预备、发力、停顿和回收姿势 |

关键姿势更多，不保证更流畅。生成图表仍可能有重复、漏格、姿势跳变和武器变形，需要检查。

下方动作示例可以帮助理解动作。它不会把你的图片实时套进示例动作。

### 4.4 补充要求并提交

点击「就做这个动作」，在「还有什么想法？」中补充要求。例如：

> 巨剑下砸后在地面停一下，再用蹬腿和转胯把剑挑起来；收招慢一点。

尽量描述一个明确变化。若同时修改脸、盔甲、武器和整个动作，后续很难判断哪个要求造成了偏差。

新手模式会自动加入动作预设、保持角色、装备一致和透明背景等要求。展开「查看实际生成要求」可以检查最终提示词。

点击「开始生成动作图表」才会提交生图任务，使用本机 Codex 的能力与账户额度。选择示例动作、播放和本地导出都不会因此提交生图。

### 4.5 等待并检查

- 一次只运行一个生成任务。
- 生图通常需要几分钟；桥接当前单次等待上限为 240 秒。
- 成功后点击「检查排版，预览动作」。
- **按照返回图片实际的行列排布确认**。提示词请求 4×4，不代表模型一定严格返回 4×4。
- 失败时读取原因，可点「修改后重新生成」，或去「任务」查看记录。

任务完成只表示拿到了合格的透明 PNG，不表示角色和动作已经通过美术验收。某个姿势画坏了，切帧工具无法自动修好。

## 5. 导入已有动作图表

### 5.1 新手导入

1. 点击「打开图表 / 项目」。
2. 选择 PNG / JPG 图表。
3. 对照弹窗里的图片，选择 4×4、4×2、2×2、8×1、3×3 或 1×1 排版。
4. 填写实际姿势数量。网格里可以有未使用的尾部格子。
5. 点击「按这个排版，预览动作」。

读取顺序固定为：从左到右，再从上到下。当前不支持跳过中间的某个格子。例如 4×4 图表填 12 帧，会读取前三行；如果空格出现在第 5 格，就需要先整理源图。

行列排布仅用于确定切图位置，不会自动解释角色的朝向、行走方向或游戏状态。

### 5.2 其他排版

进入「进阶编辑」，在「图表切帧」中填写列数、行数、帧数和原生尺寸，再点击「建立动画时间轴」。

当前限制：列数 1–8、行数 1–8、每个动作 1–32 帧，帧数不得超过格子总数。支持规则网格，不支持任意不规则裁框。

### 5.3 适合导入的图表

每格应包含一个完整人物，人物与剑、刀光都不要跨进相邻格子。原图已经把剑尖裁掉时，应先修复原图；扩大输出画布无法恢复丢失的像素。

只导入单张角色图，会得到单帧预览。导出成 GIF 文件也不会凭空产生动作。当前不支持直接导入 GIF 并自动拆帧。

## 6. 在简化预览中检查动作

先播放一次看整体，再逐帧看变化。

| 控件 | 用法 |
|---|---|
| 播放 / 暂停 | 查看实际时间轴；空格也可控制，需先让画布获得焦点 |
| 上一帧 / 下一帧 | 定位不连贯的姿势 |
| 时间轴缩略图 | 点击后跳到对应帧并暂停 |
| 0.5× / 1× / 2× | 临时改变观看速度，不改导出时长 |
| 循环 | 控制预览与导出 GIF 是否循环 |
| 背景色 | 用棋盘、深色、浅色检查透明区和边缘 |
| 放大 / 缩小 / 适应画布 | 改变查看大小，不改原生素材尺寸 |
| 精细调整 | 展开完整编辑器 |

优先检查：角色是否突然跳位，剑是否变短，动作是否缺少中间过程，收招是否太快，身体或刀光是否被裁切。

## 7. 进入进阶编辑

### 7.1 四个工作区

- **创作**：参考图、动作预设、提示词、单张姿势 / 动作图表生成。
- **动画**：图表处理、时间轴、逐帧校准。
- **素材**：参考图收藏和生成结果。
- **任务**：状态、提示词、失败原因和生成记录。

首页右上角「进阶编辑」也可以进入。左侧「开始」随时返回新手首页。

### 7.2 生成方式

「单张姿势」适合验证角色母版、武器和某个关键姿势；「动作图表」要求生成连续关键姿势。

选择动作预设会重置动作要求文本。已经手写了重要要求时，先复制保存，再切换预设。

独立动作默认预设含双手巨剑假设。打开法杖角色工程后，会改用法杖动作配方；其他装备与无武器人物仍需检查并改写要求，不能仅替换参考图就认为动作已经适配。

### 7.3 参数解释

| 参数 | 含义 | 修改时注意 |
|---|---|---|
| 列数 / 行数 / 帧数 | 源图排布与读取数量 | 按实际图片填写；切错后整个人物会被分开 |
| 原生尺寸 | 每帧输出画布大小 | UI 提供 128、160、192、224、256、320 像素的正方形 |
| 停留时长 | 当前帧显示多久 | 10–2000ms，按 10ms 递增 |
| 水平 / 垂直偏移 | 当前完整姿势在输出画布内移动 | 支持 -300 至 300 的整数像素 |
| 源图采样倍率 | 所有帧共用的缩放 | 0.01–8，改变全部姿势的尺度，不是画布查看倍率 |
| 根节点 X / Y | 整个动作共用的逻辑锚点 | 要在画布内，后续与游戏角色位置对应 |
| 统一色板 | 当前动作导出时使用的颜色数量上限 | 32 / 64 / 128 / 255，较少颜色可能丢细节 |
| GIF 倍率 | 导出预览的整数放大 | 1× / 2× / 4×，不会放大 PNG 原生帧 |

切帧初始化时，工具会基于所有姿势的透明区域联合范围，计算一个共用缩放和基准偏移。之后每帧可以做显式整帧平移。

重新点击「建立动画时间轴」会重新建立帧数据，现有逐帧偏移和时长可能被重置。重要修改先保存项目。

## 8. 处理接地、抖动与裁切

### 跑步某一帧突然跳一下

1. 暂停，点击问题帧。
2. 打开「前帧叠影」，对照头部、胸甲和腰部位置。
3. 打开「锚点参考线」。它表示固定逻辑位置，不会自动检测脚底。
4. 微调整帧的水平 / 垂直偏移。
5. 检查前后两帧，慢速播放，再恢复 1×。

把每一帧最低的脚尖强行贴同一条线，可能破坏正常的摆腿、屈膝和腾空。应结合支撑脚与身体重心判断。

画布获得焦点后，可用 Alt + 方向键每次移动当前整帧 1px。快捷键移动完整姿势，不会拆开四肢或改变剑柄。

### 跳跃应该怎么对齐

保持逻辑锚点一致，同时保留人物腾空和落地缓冲。不要为了“脚底齐平”消除跳跃高度。

### 剑或刀光被裁掉

- 输出画布太小或偏移过大：调整统一采样倍率、整帧偏移；必要时另存项目，再重建更大画布。
- 源图格子已经裁掉了剑尖：修复源图或重生成对应姿势。
- 导出提示“第 N 帧超出画布”：先检查该帧，工具会阻止这次导出。

### 「将当前偏移应用到全部帧」

它会把当前帧的偏移值复制给所有帧，覆盖原有偏移。它不判断每一帧的脚底位置，也不是自动对齐功能。

## 9. 调整动作节奏

帧数与播放速度是两回事。8 帧每帧 100ms，总时长是 0.8 秒；把其中一帧改为 200ms，总时长就增加 0.1 秒。

可以先按这些思路手动调整，然后在游戏里验证：

| 动作阶段 | 调整思路 |
|---|---|
| 预备 / 蓄力 | 稍长，给观众看清发力意图 |
| 发力与挥击 | 较短，让动作形成速度差 |
| 下砸触地 | 挑一个接触姿势短暂停留，强调重量 |
| 地面转上挑 | 保留屈膝、转髋、挺身与高位随挥的连续过程 |
| 收招 | 给角色回收惯性的时间，避免瞬间弹回站姿 |

这些是调整起点，不是固定毫秒标准。缺少关键姿势时，仅延长帧时长无法补足动作。

0.5× / 2× 用于预览比较。最终输出使用每帧保存的停留时长。挥击是否有打击感，还要结合游戏里的命中、敌人反馈、音效和镜头验证。

## 10. 保存与继续修改

### 保存项目

点击「保存项目」，下载 JSON 文件。当前项目文件包含：

- 当前源图的嵌入图片数据。
- 动作名称与提示词。
- 图表排布、原生尺寸、共用缩放和基准位置。
- 各帧偏移、各帧时长、锚点。
- 色板数量、GIF 倍率与循环选项。

通过首页「打开图表 / 项目」选择该 JSON，即可恢复可编辑动作。

「保存项目」下载的 JSON 仍以单个动作为主；完整多动作工程请使用「角色工程 → 下载可编辑工程JSON」。单动作文件不包含整套聊天上下文。导出包中的 `animation.json` 是运行资源说明，不能代替保存项目 JSON。

### 防止丢进度

浏览器草稿与角色工程现已支持自动保存和恢复。确认右上角保存状态后再关闭；重要修改仍建议下载项目 JSON 作为独立备份。

生成任务和已完成图片会保存在本机 `work/`。时间轴另由浏览器草稿保存；加入角色工程的动作也会保存到工程文件。

## 11. 导出与游戏接入

### 11.1 审片、标记与导出

1. 打开角色工程或已切好的动作，进入「交付」。用动作下拉框切换角色已有的动作。
2. 将「绘制倍率」设成游戏里的整数像素倍率。先原速看一遍，再用半速或四分之一速看接地、武器路线和首尾。地面和十字是逻辑锚点参考。高倍率可以在预览框中滚动。
3. 点击下方小图暂停在该帧。「去编辑所选帧」会带你回动作编辑。「自动检查」里的每条问题也可直接定位。透明、贴边和裁切问题优先修正，然后回到「交付」复查。
4. 在攻击的接触帧标记命中，或在远程／施法动作的释放帧添加标记。每次点击切换当前帧的标记，再次点击即可取消。事件列表会显示累计时间。重新切分图表后，按新的帧顺序重新标记。
5. 逐项完成「人工验收」。勾选按当前动作内容保存在本机。导出的技术状态可用于交接，视觉与游戏状态需要对应的实际验证。

在「交付」可导出当前动作或整套角色。

简化模式点击「制作并下载 GIF」会打开导出并开始整理。进阶模式点击「导出素材」或「生成 GIF / 资源包」，再点击「导出透明动画」。

完成后可以分别下载 GIF 和 ZIP。

### 11.2 ZIP 里有什么

```text
assets.zip
├── frames/
│   ├── 00.png
│   ├── 01.png
│   └── ...
├── atlas.png
├── animation.json
├── palette.json
├── source.png
└── preview.gif
```

| 文件 | 用途 |
|---|---|
| `frames/*.png` | 原生尺寸透明帧，适合继续编辑或导入引擎 |
| `atlas.png` | 4 列排布的透明图集；末尾可能存在空格 |
| `animation.json` | 帧位置、时长、锚点、动作事件和输出帧的技术检查结果 |
| `palette.json` | 本次动作导出的实际色板 |
| `source.png` | 原始图表副本 |
| `preview.gif` | 分享与预览，按选择的倍率放大 |

导出采用当前动作范围内的统一色板，Alpha 阈值为 220，输出为二值透明。GIF 可以透明，但不支持 PNG 那样的连续半透明；烟雾和柔光的边缘可能变化。

独立动作默认统一本次导出的色板；打开冻结的角色工程后，动作导出会使用工程色板。整套导出要求全部动作使用工程规定的画布和锚点。

### 11.3 原地动画与游戏位移

角色冲刺时在游戏里走多远，应由程序控制。图像中的完整姿势可以有必要的重心变化，但逻辑根节点保持一致，输出配置的根位移为零。

图集的格子大小包含透明空间和巨剑空间，不宜直接用作攻击范围或碰撞盒。攻击距离、有效命中帧、伤害、挑飞与击退需要另行配置并在游戏中验证。

工作台 JSON 还不是 Unity、Godot 或其他引擎的通用导入格式。接入时按 `rect` 取帧、按 `duration_ms` 播放，并将各帧共用的 `pivot` 对齐游戏中的角色位置。详细约定见 [游戏接入说明](engine-integration.md)。

## 12. 参考库、版本与任务

### 素材库

- 点击「收藏为角色参考」保存当前参考。
- 「导入角色参考」将图片加入本机参考库。
- 支持按类型筛选和名称搜索。
- 「设为参考」用于下一次生成，不会自动修改已经做好的动作。

### 生成版本

已完成的结果会进入版本记录。选择一个版本，再点「基于此图修改」，把它作为下一次生成的参考图。

当前每个新生成任务使用独立的临时 Codex 会话；界面中的“继续修改”通过传入已有图片实现，不是复用此前全部对话上下文。

多次修改后若角色已经偏离母版，应回到通过检查的参考图重新生成，避免继续沿用错误结果。

### 任务

任务区可以查看状态、生成要求、错误信息与记录。关闭或刷新页面后会尝试恢复浏览器草稿；如果草稿不可用，可以从任务与素材区找回已保存的结果。

### 本机存放位置

以下路径均相对于项目根目录：

```text
work/image-workbench/<任务ID>/      参考图、生成图、任务记录
work/image-workbench/references/    收藏的角色参考
work/image-workbench/examples/      本机示例动作
work/image-workbench/exports/       每次独立导出的资源
```

`work/` 默认不进 Git 和分享包。给别人传项目时，需要明确附上希望分享的项目 JSON 或资源包。它们可能包含角色源图，不应当作不含素材的纯配置文件。

## 13. 常见问题

| 情况 | 原因与处理 |
|---|---|
| 打不开 8898 | 检查服务是否启动、终端是否退出，是否有其他程序占用端口 |
| 显示桥接已连接，却生图失败 | HTTP 服务连接与模型可用性不同；查看任务中的实际错误 |
| 新安装没有女骑士 | 本机示例没有包含在源码包中；上传自己的素材即可继续 |
| 选了动作，自己的角色却没有动 | 点击卡片只是预览已有示例；需提交生成并等待完成 |
| 导入图片后人物被切开 | 行列数不符，或源图不是等尺寸规则网格 |
| 导出提示空白帧 | 读取数量包含了空格，或姿势已被移出画布 |
| 背景仍是白色 / 黑色 | 图表本身没有透明背景；切换画布底色不会去背景 |
| 角色越来越小或武器忽大忽小 | 检查原始姿势；统一缩放不会修复模型画出的比例变化 |
| 改了缩放后所有帧都变了 | 采样倍率本来就由整个动作共用；若仅调一帧位置，使用 XY 偏移 |
| 重建时间轴后调整没了 | 切帧会重新初始化数据；先保存项目再重建 |
| GIF 动作很快或很慢 | 检查帧时长与循环边界；预览倍速不改最终导出速度 |
| 想只修一帧 | 外部重画一个同尺寸透明PNG，通过「替换当前完整帧」替换；尚无模型自动单帧返工 |
| 想一键生成全部八个动作 | 当前需要逐个动作生成和检查，没有批量自动排程 |
| 刷新后原来的选择不见了 | 检查保存状态、浏览器站点数据和恢复错误；必要时导入下载的项目/角色工程JSON |
| 只想分享 GIF | 下载 `preview.gif`；需要给研发则一并提供 PNG、图集、配置与玩法说明 |

## 14. 一套动作的验收清单

### 看美术

- [ ] 人物头身比例、发型、服装、脸与参考一致。
- [ ] 像素密度一致，没有突然出现平滑插画或模糊帧。
- [ ] 武器长度、宽度、剑柄方向与握持点稳定。
- [ ] 没有多手、缺脚、关节反折或人物和武器分离。

### 看动作

- [ ] 有预备、发力、惯性与回收过程。
- [ ] 跑步没有不合理的整个人物跳位。
- [ ] 跳跃保留腾空与落地缓冲。
- [ ] 连段下砸接上挑时，腿、髋、躯干和肩臂共同发力。
- [ ] 刀光沿剑刃轨迹出现，大小没有代替真实攻击范围。
- [ ] 循环首尾衔接合理；非循环动作有明确结束状态。

### 看交付

- [ ] 所有帧完整，没有被裁掉的身体、剑或刀光。
- [ ] 透明区域正确，深色和浅色背景下都检查过边缘。
- [ ] 原生尺寸、锚点和帧时长已保存。
- [ ] 保存了可编辑项目 JSON，同时导出了资源包。
- [ ] 游戏中检查过绘制位置、移动速度、命中距离与结束状态。

## 15. 当前能力边界

已实现：参考图生图、动作简报、单张 / 图表输出要求、新手引导、示例预览、本地图表切帧、统一尺度、整帧偏移、逐帧时长、透明导出与项目恢复。

仍需要人工：确认模型返回排版，检查身份与武器一致性、关节发力、接地和循环，修复画坏的姿势，完成引擎适配和实机验收。

尚未实现：经过大规模验证的跨角色模板库、批量生成、自动补帧、自动关节修复、自动背景移除、模型自动单帧返工与自动游戏接入。

当前验证覆盖女骑士和紫袍骷髅法师，以及本地功能测试；尚无跨角色、跨武器的大规模成功率数据。
